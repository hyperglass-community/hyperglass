# User guide

Hyperglass provides a web form for running the network queries that an administrator has enabled. The available locations, query types, target validation rules, and result fields depend on the deployment configuration.

## Run a query

### Choose a location

Select one or more routers or locations from which the query should run. Each location determines the network path and device that will execute the command.

Deployments with a small number of locations may show them as cards. Larger deployments usually show a dropdown.

When you select multiple locations, Hyperglass shows query types available on every selected device. Devices from different vendors may use different commands for the same query type; Hyperglass selects the correct command for each device.

### Choose a query type

- **Ping** tests reachability and reports round-trip time.
- **Traceroute** shows the path toward a destination and may include hop latency, packet loss, ASN, organisation, country, IXP, or reverse DNS details.
- **BGP route** shows routes for an IP address or prefix when the selected device supports the configured directive.
- **BGP community** finds routes associated with a community value.
- **BGP AS path** finds routes that contain one or more ASNs.

### Enter a target

Depending on the query type, enter an IP address, hostname, prefix, or ASN. Examples include `8.8.8.8`, `2001:4860:4860::8888`, `8.8.8.0/24`, `google.com`, and `AS15169`.

The deployment may restrict target formats or networks. A rejected target means the administrator's query policy did not allow it, not that the device is unreachable.

### Submit the query

Some query types show additional select fields. Select only the options you need; fields marked as required must have a value.

Select **Submit** to run the query. The page shows the response when the device finishes, or an error message when the query cannot complete.

Use the browser Back button or the in-page back control to return to the form with your last query selections. Select the title link to clear the form.

## Link to a filled-in form

A link can fill in the form, for example from a ticket, a monitoring tool or documentation. Add these parameters to the address of the Hyperglass page:

| Parameter        | Value                                                                                                                 |
| :--------------- | :-------------------------------------------------------------------------------------------------------------------- |
| `location`       | A location's device ID. Repeat it to select several locations.                                                        |
| `type`           | A query type's directive ID, or its name as the form shows it, such as `BGP Route`.                                   |
| `target`         | The query target. For a query type with a list of targets, one of the listed values.                                  |
| `var.<variable>` | The value of a directive variable, by the variable's ID, such as `var.vrf=default`. Use one of the variable's values. |

```text
https://lg.example.net/?location=router_one&location=router_two&type=BGP+Route&target=2001:db8::/32
```

A device ID is made from the device's `name` in `devices.yaml`: characters other than letters, digits, `_`, `-` and spaces are removed, each run of spaces becomes `_`, and the result is lowercased, so `Router One` becomes `router_one`. The `id` of each location is also listed by `/api/devices`.

The link only fills in the form; the query runs when you select **Submit**. A required greeting must still be acknowledged, and a hostname target is still resolved first.

Values that the deployment doesn't offer are left out without a message: an unknown location, a query type that the selected locations don't share, a target that isn't one of the listed values or that contains control characters or line breaks, or an unknown variable or value. The query type is only filled in when at least one location is valid, and the target and variables only when the query type is. When the selected locations have only one query type in common, the form chooses it; a link without `type` then fills in the target and variables for it, and a link with a different `type` doesn't.

With locations from different vendors, the query type can be given by its name or by any selected location's directive ID for it.

Encode the values as in any URL query string: a `+` reads as a space, so encode a literal `+` as `%2B`, and a `%` (such as in an IPv6 zone, `fe80::1%25eth0`) as `%25`. IPv6 addresses and prefixes need no other encoding. A link sets one target.

Once the form is filled in, Hyperglass removes these parameters from the address bar, so the address doesn't keep describing a query you have since changed. Other parameters and the `#` fragment stay.

### Copy a link to a query

After you submit a query, select the link button above the results (**Copy Link**) to copy a link to it. The link has every selected location, the query type, the target and any variables, in the parameters above, added to the current address of the page (its origin and path). Other parameters of your address and the `#` fragment are not included. Behind a reverse proxy, the link is only as good as that address: after a link to a filled-in form has been opened, the address can end without its trailing slash (`/tools/lg` instead of `/tools/lg/`), so the proxy must serve that path too, or redirect it.

The link shares the query, not its result: whoever opens it gets the form filled in and selects **Submit** to run the query again. When the query had a hostname target, the link has the address it was resolved to, as that is what was queried.

If the browser can't copy (for example on a page served over plain HTTP, or when clipboard access is refused), the link appears in a read-only field below the button, selected, so you can copy it yourself.

## Share a result

When the deployment has [sharing](/configuration/config/share) on, each successful result has a share button (**Share Result**) next to the copy and requery buttons. It isn't offered while a result's AS path details are still loading, or for query types the operator keeps out of history and shares.

1. Select the share button.
2. Under **Keep for**, choose how long the link works.
3. Select **Create Link**.

The popover shows the link, ready to copy with **Copy Link** (or to copy yourself from its field when the browser can't), and when it expires. Anyone with the link can see the result, including the target you queried. The link is to this result as it is now: the same output whenever it is opened, until it expires.

**Delete Link** removes the link at once. The key that allows it is kept in this browser, with the link, so you can delete it later from the same popover or from "Your shared links" (see below), also after closing the page. Sharing the same result again while it is still cached gives you the same link back, with a new key. That new key replaces the old one: if the result was shared again from another browser on your network, this browser can no longer delete the link, and says so; the link keeps working until it expires.

When you run the query again, the new result can get its own link. Links you made from the earlier results stay in the popover, labelled with the time of their result, so you can still copy or delete them.

### Share a saved query

When the deployment also keeps your recent queries ("Recent queries", under the form), a saved result has the share button too: on each result of an opened saved query, and on the row of a saved query of one location. The server can only share a result it still holds, which is only for a short time after the query ran (two minutes by default). When it no longer holds it, the popover says so and offers **Run again**, which runs the query again for a new result you can share. A saved query whose result has a link is marked **Link shared**.

### Your shared links

The links you create in this browser are listed under **Your shared links**, below the form, with what was shared, when the result was produced and when the link expires. You can copy or delete each one there, from any tab and after reloading the page, whether your recent queries are kept or not. Deleting saved queries doesn't delete their links. **Forget all** removes the list from this browser but not the links: they keep working until they expire, and can no longer be deleted from here. On a deployment set up for shared computers, the links are kept only until you close or reload the page.

## Open a shared result

When the deployment has [sharing](/configuration/config/share) on, a link such as `https://lg.example.net/?share=<id>` shows a copy of a result someone shared, kept on the server: the same output whenever it is opened, until the link expires. The page shows when the result was produced and when the link expires, in your time zone. You can copy the output, but not run it again from there. **Run this query** fills in the form with the shared query, for you to submit; **New query** shows an empty form. A share link that also has form parameters (`location`, `type`, `target`, `var.*`) ignores them.

## Hostname resolution

When you enter a hostname instead of an address, Hyperglass resolves it through the configured DNS provider. The resolver returns available IPv4 and IPv6 addresses, and you choose which address to query.

<Callout type="info">Public DNS-over-HTTPS providers receive requests from your browser. In server mode, Hyperglass resolves the hostname using the server's resolver instead.</Callout>

1. Enter a hostname such as `google.com`.
2. Select **Submit**.
3. Select an IPv4 or IPv6 address in the resolution dialog. Hyperglass runs the query against that address.

If no address is returned, check the hostname, the configured DNS provider, and any browser or network policy that blocks the resolver request.

## Use My IP

The **My IP** control offers your detected address as a query target. By default the server detects it. The administrator can instead use external detection, or hide the control.

1. Select **My IP** beside the target field.
2. Confirm the lookup if the notice says it sends your IP address to myip.wtf.
3. Choose an available address.
4. Submit the query as usual.

External detection can return IPv4 and IPv6 addresses. If it fails, the server detects the address instead. Server detection returns only the address family used for your request and does not contact myip.wtf. The detected address can differ from your device address behind NAT, a VPN, or a corporate proxy.

## Read results

The result panel may include raw device output, parsed tables, route metadata, AS path links, traceroute hop details, or a query error. Structured output is available only when both the deployment and the selected device support it.

Traceroute tables preserve device-reported statistics. Where those statistics are absent, Hyperglass derives Last, Best, and Worst from available probe RTTs. It derives Loss only when the parser knows the number of sent probes. A missing RTT alone does not establish packet loss.

Cached results show a cache indicator and the time at which the result was created. A cached response is still a response from a previous query. Run the query again when you need current device output.

## When a query fails

Check the target format first, then try another location if one is available. If the problem continues, report it to the operator of that Hyperglass deployment with the location, query type, target format, approximate time, and visible error message. Do not include credentials or private device output in a public report.
