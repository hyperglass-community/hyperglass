## Web UI

Hyperglass provides extensive customisation options for the look and feel of the web UI.

| Parameter                   | Type   | Default Value | Description                                                                                                                                |
| :-------------------------- | :----- | :------------ | :----------------------------------------------------------------------------------------------------------------------------------------- |
| `web.location_display_mode` | String | auto          | Show the locations field as a `dropdown` or a `gallery`. `auto` uses `gallery` when there are fewer than 5 location groups and every group has fewer than 9 locations, and `dropdown` otherwise. |
| `web.custom_javascript`     | String |               | Path to a JavaScript file that is loaded in the page head. The file must exist.                                                            |
| `web.custom_html`           | String |               | Path to a custom HTML file that is rendered beneath the app. The file must exist.                                                          |
| `web.my_ip` | String | server | How the My IP button finds the visitor's address. `server` returns the address Hyperglass received the request from, so no third party is contacted. Behind a proxy listed in `web.client_ip.trusted_proxies`, it reads the forwarded client address. Only the address family used for the request is shown, and an address that is not public is not shown. `external` is opt-in: it asks myip.wtf, which can return both IPv4 and IPv6, after showing `web.text.ip_lookup_notice` and waiting for the visitor to confirm. If the myip.wtf lookup for a family fails, the button falls back to the server address for that family. `off` hides the button. |

### DNS over HTTPS

By default, the browser resolves hostname targets using [DNS over HTTPS](https://www.rfc-editor.org/rfc/rfc8484). Set `web.dns_provider.name: server` to send the lookup through the Hyperglass server instead. The server then asks `web.server_lookups.dns.resolver`, Cloudflare's public resolver by default. See [Data Sent to Third Parties](/configuration/third-party-data) for what each option sends.

| Parameter           | Type   | Default Value                          | Description                                                                 |
| :------------------ | :----- | :------------------------------------- | :-------------------------------------------------------------------------- |
| `web.dns_provider.name` | String | cloudflare                             | If `cloudflare` or `google` are provided, no URL is necessary. Use `server` to resolve hostnames through `/api/dns` on the Hyperglass server (public A and AAAA records only), so the visitor's browser sends no DNS query to a third party. See [Optional server lookups](#optional-server-lookups). |
| `web.dns_provider.url`  | String | `https://cloudflare-dns.com/dns-query` | Provide a custom DNS over HTTPS URL if you'd like to use your own resolver. A URL that is not a built-in provider URL sets the provider name to `custom`. |

```yaml filename="config.yaml" copy
web:
    dns_provider:
        name: server
    my_ip: server
```

With this configuration the browser asks `/api/dns` for hostname targets and `/api/myip` for the visitor address. The browser contacts no public DNS-over-HTTPS provider and not myip.wtf. The Hyperglass server sends each DNS lookup to `web.server_lookups.dns.resolver`, Cloudflare's public resolver at `https://1.1.1.1/dns-query` by default. Font downloads and optional enrichment services have separate network requirements.

Server DNS supports A and AAAA records. Server My IP returns only the address family used for the request. Both endpoints identify the client as described under [Client Address](#client-address). Configure your reverse proxy to overwrite client-address headers with verified values.

### Client Address

Hyperglass needs the visitor's address for server My IP, for the per-client lookup limits, for the [query rate limit](/configuration/config/query-limit) and for the webhook `source` field. By default it uses the address of the connection and ignores forwarding headers. Behind a reverse proxy, list the proxy in `web.client_ip.trusted_proxies`. Hyperglass then reads the forwarded address from connections that come from those networks.

| Parameter | Type | Default Value | Description |
| :-------- | :--- | :------------ | :---------- |
| `web.client_ip.header` | String | | Single-address request header that the trusted proxy overwrites, such as `X-Real-IP` or `CF-Connecting-IP`. Hyperglass reads it only from a trusted proxy and does not fall back to another header. The name is not case-sensitive. When unset, Hyperglass reads `X-Forwarded-For`. |
| `web.client_ip.trusted_proxies` | List of networks | `[]` | IPv4 and IPv6 networks of the proxies that connect to Hyperglass. Hyperglass reads client address headers only when the connection comes from one of these networks. Any other connection is treated as the client. When the list is empty, Hyperglass ignores the headers. |

Set `web.client_ip.header` when a CDN is in front of your reverse proxy. The reverse proxy then sees the CDN as its client, so `X-Real-IP` holds a CDN address. The CDN sends the visitor's address in its own header, such as `CF-Connecting-IP` (Cloudflare), `True-Client-IP` (Akamai) or `Fastly-Client-IP` (Fastly).

Set `web.client_ip.trusted_proxies` on every installation behind a reverse proxy. List the networks that connect to Hyperglass directly, which is normally your reverse proxy and not the CDN. Without a `header`, Hyperglass reads `X-Forwarded-For` from the right and uses the last entry that is not a trusted proxy, so an entry that the client added is ignored.

```yaml filename="config.yaml" copy
web:
    client_ip:
        header: CF-Connecting-IP
        trusted_proxies:
            - 172.16.0.0/12
            - fd00::/8
```

<Callout type="warning">
Your reverse proxy must pass the CDN header only for requests that come from the CDN. If the proxy also accepts requests from other sources, remove the header from those requests at the proxy.
</Callout>

### Optional server lookups

The DNS and AS-path enrichment endpoints are disabled by default. Enable them explicitly in `config.yaml`, then restart Hyperglass:

```yaml
web:
    dns_provider:
        name: server
    aspath_enrichment: true
    client_ip:
        trusted_proxies: ["192.0.2.10/32"]
        # Set this only when the proxy overwrites this single-address header.
        # header: X-Real-IP
```

Replace the example proxy address with the address that actually connects to Hyperglass. An empty `trusted_proxies` list ignores all forwarding headers. Without a custom `header`, Hyperglass reads `X-Forwarded-For` from right to left, stopping at the first untrusted address. A custom header has no fallback to other headers. Configure the proxy to overwrite that header and prevent direct access to the application port.

The normal Hyperglass launcher disables Uvicorn's proxy-header rewriting so the application can verify the socket peer. When running Uvicorn directly, pass `--no-proxy-headers`. Otherwise, upstream rewriting can replace the peer before Hyperglass checks it.

Server DNS uses the DNS-over-HTTPS JSON endpoint in `web.server_lookups.dns.resolver`, by default Cloudflare's public resolver at `https://1.1.1.1/dns-query`. It does not use operating-system DNS, search domains, environment proxies, or redirects. Only public A and AAAA answers are returned. Internal DNS resolution is not supported by this public endpoint. Browser DNS providers keep the server endpoint disabled.

By default, DNS permits 120 requests per client and 600 requests globally per 60-second window, and AS-path enrichment permits 30 requests per client and 120 requests globally per window. A client is one IPv4 address or one IPv6 /64, so a host cannot multiply its quota by rotating addresses within its prefix. Redis shares these limits across workers. Storage failures deny lookups. Both endpoints share eight outbound lookup slots and a five-second lookup deadline by default. AS-path lookups go to the WHOIS server in `structured.ip_enrichment.whois_host` and `whois_port`. The endpoints return HTTP 429 when request limits are reached and HTTP 503 when outbound capacity or required storage is unavailable.

AS-path requests accept at most 64 ASNs and an 8 KiB body. ASNs must be decimal integers between 1 and 4294967295. Duplicate ASNs are removed before lookup. Results use shared caches: DNS answers for up to 60 seconds, negative DNS responses for 15 seconds, and ASN names for one hour. Disabling `web.aspath_enrichment` also stops the AS-path modal from requesting enrichment.

Set these bounds under `web.server_lookups`:

```yaml filename="config.yaml"
web:
    server_lookups:
        timeout: 5          # seconds per outbound lookup, whole seconds
        max_concurrent: 8   # outbound lookups in flight, across all workers
        dns:
            resolver: https://1.1.1.1/dns-query
            client_limit: 120   # requests per minute per client
            global_limit: 600   # requests per minute in total
        aspath:
            client_limit: 30
            global_limit: 120
```

See the [complete configuration reference](/configuration/config/complete-config#basic-web-settings) for each key.

### My IP and reverse-proxy upgrades

`web.my_ip: server` uses the request address for the My IP button. Non-public addresses return `null`, leaving the input unchanged. This mode does not fall back to a public IP service. Set `web.my_ip: external` explicitly to use a public IP service from the browser. That setting does not change webhook attribution.

**Upgrade requirement:** forwarding headers now require an explicitly trusted proxy. Existing nginx installations must configure `web.client_ip` to retain visitor addresses for My IP, webhook `source`, and per-client limits. An empty `trusted_proxies` list uses the socket peer, so webhooks report the proxy address until configured.

For nginx on the same host, connecting to Hyperglass over loopback, add this to `config.yaml`:

```yaml
web:
    my_ip: server
    client_ip:
        trusted_proxies: ["127.0.0.1/32", "::1/128"]
        header: X-Real-IP
```

In the nginx location that proxies requests to Hyperglass, overwrite the forwarding headers:

```nginx
location / {
    proxy_pass http://[::1]:8001;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $remote_addr;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

Hyperglass listens on `[::1]` by default. Use the configured `HYPERGLASS_HOST` address and port in `proxy_pass`, for example `http://127.0.0.1:8001` when `HYPERGLASS_HOST=127.0.0.1`. Keep Hyperglass bound to loopback for this setup. Restart Hyperglass and reload nginx after updating both configurations. For a container or remote proxy, trust its actual connecting address instead of loopback. Do not trust all networks. This example assumes visitors connect directly to nginx; a CDN or additional proxy requires its own explicit trust configuration in nginx.

### Query history

Each browser keeps the queries it ran successfully and lists them under "Recent queries" on the landing page. A visitor can open a saved query to see its results again, delete it, or delete them all with **Clear all**, which asks for confirmation first. An opened query shows the saved output as it was: nothing is sent to the server or to the device, and the browser's Back button, or the **Back** button above the results, closes it.

| Parameter            | Type    | Default Value | Description                                                                                            |
| :------------------- | :------ | :------------ | :----------------------------------------------------------------------------------------------------- |
| `web.history.enable` | Boolean | `true`        | Keep successful queries in the visitor's browser and list them under "Recent queries".                 |
| `web.history.limit`  | Integer | `10`          | Number of queries each browser keeps, from 1 to 50. The oldest is removed when a new one is saved.     |

What is stored, and where:

-   For each query: the locations, the query type, the target, the query's variables, the time it was saved, and each location's output, with the output's query ID.
-   Only results that succeeded are saved. A query that failed on every location is not saved.
-   Results of a directive with [`retain: false`](/configuration/directives.mdx#keep-results-out-of-history) are not saved.
-   History is kept in the browser's local storage, under the `hyperglass.history` key. It is never sent to the Hyperglass server and is not shared between browsers or devices.
-   The "My IP" button makes the visitor's own address the query target, so that address is saved with the query.
-   When local storage is full, the oldest saved queries are removed until the new one fits. When the browser does not allow local storage (some private browsing modes), history lasts until the page is closed or reloaded.
-   All tabs of a browser share one history: a query deleted or cleared in one tab is gone from the others too.
-   Saved queries this version of Hyperglass can't read, such as history saved by another version in another format, are not shown and are deleted from the browser when the page loads.
-   History saved by hyperglass-ng, under the `hyperglass.queryHistory` key, is not migrated: it is deleted from the browser when the page loads, whether history is on or off.

Visitors delete history with the **Delete** button of a query, with **Clear all**, or by clearing the site's data in their browser.

<Callout type="warning">
Turn history off on kiosks and shared terminals, where the next person to use the browser would see the previous person's queries. With `enable: false`, nothing is saved and the history a browser saved before is deleted when it next loads the page.
</Callout>

##### Example

```yaml filename="config.yaml" copy
web:
    history:
        enable: true
        limit: 20
```

### Highlighting

Hyperglass can highlight special values in router output and provide users with additional context. For example, an organisation's BGP communities or IP address space can be highlighted with a tooltip.

`web.highlight` is a list. Each value you wish to be highlighted is defined with the following schema:

| Parameter | Type   | Default Value | Description                                             |
| :-------- | :----- | :------------ | :------------------------------------------------------ |

| `label`   | String |               | Tooltip value when the highlighted text is hovered.     |
| `color`   | String | primary       | Color name from [`web.theme.colors`](#colors).          |

##### Example

```yaml filename="config.yaml" copy
web:
    highlight:
        - pattern: "65000:1234"
          label: Special snowflake community that does a thing
          color: primary
        - pattern: '^192\.0\.2\.[0-9]+$'
          label: Magical IP Address
          color: blue
```

```yaml filename="config.yaml" copy
web:

    - title: Terms & Conditions
      content: |

      side: right
      order: 1
    - title: Help
      content: /path/to/help/file.md
      side: left
      order: 0
```

### Requery button

Each result has a requery button that runs its query again. With [`cache.refresh.enable`](/configuration/config/caching#forced-refresh) set to `false`, the default, the server answers it from the cache while the result is cached, so the output is the same.

With `cache.refresh.enable: true`, the button sends that one request with `force`, so the query runs on the device again and the result is replaced. Every successful response says when the next forced run is allowed (`refresh_in`), counted from when the response arrived in the browser. A press before then sends no request: `web.text.refresh_cooldown` appears under the result's header, counting down to zero. Screen readers announce the time left once per press, not on every second. The button stays enabled during the cooldown, so it keeps its tooltip and can say why nothing happened.

If a press is answered from the cache because the server's cooldown is still running (another visitor refreshed the same query, or an earlier forced run failed), the countdown appears at once.

A failed response carries no cooldown, so the next press after a failure sends a forced request.

###### Example

To override Hyperglass's primary colour, override its mapped intrinsic colour. For example, to override the default primary colour to <Color hex="#00ffff" noText /> cyan:

```yaml filename="config.yaml"
web:
    theme:
        colors:
            cyan: "#00ffff"
```

#### Fonts

Hyperglass's fonts come from [Google Fonts](https://fonts.google.com/). The default fonts, Nunito and Fira Code, ship with hyperglass under the SIL Open Font License. The UI build serves them itself without network access, so neither the server nor visitors' browsers contact Google.

Any other Google font name may be specified to override the default fonts. By default, the server does not download it, and visitors' browsers load it from Google Fonts. Set `web.theme.fonts.download` to `true` to have the server download non-default fonts from Google when the UI is built and serve them itself. If that download fails, for example on a server without internet access, the UI links Google Fonts instead.

<Callout type="warning">
**A non-default font sends visitors to Google unless `download` is `true`.** Each visitor's browser requests the font from `fonts.googleapis.com` and `fonts.gstatic.com`, which reveals the visitor's IP address to Google. To serve it from your own server, set `web.theme.fonts.download: true`, and check that the server can reach Google Fonts when the UI is built.
</Callout>

The font name is matched exactly against the bundled families. Write `Nunito` and `Fira Code` as shown; another spelling, such as `nunito`, is treated as a non-default font.

| Parameter                  | Type    | Default Value | Description                                                                              |
| :------------------------- | :------ | :------------ | :--------------------------------------------------------------------------------------- |
| `web.theme.fonts.body`     | String  | Nunito        | Font for all standard body text, including headings.                                     |
| `web.theme.fonts.mono`     | String  | Fira Code     | Font for all monospace text such as inline code or code blocks, including device output. |
| `web.theme.fonts.download` | Boolean | `false`       | Download non-default fonts from Google Fonts when the UI is built, and serve them.       |

##### Example

```yaml filename="config.yaml"
web:
    theme:
        fonts:
            body: Inter
            download: true
```
